# コマあわせ 紹介動画

SNS 向けの30秒の紹介動画（縦 9:16 と横 16:9）のソース。動画は HTML で組み、MP4 はここから書き出す。MP4 はリポジトリに入れない。

## ファイル

| ファイル | 中身 |
|---|---|
| `video/index.html` | 動画そのもの。GSAP のタイムラインで全場面を組み、曲は Web Audio API で鳴らす。ブラウザで開くと再生できる（右上で縦・横を切り替え、`#v` `#h` でも指定できる） |
| `video/shots/` | 動画に出てくるアプリの画面。実際のアプリをデモデータで撮ったもの |
| `seed.mjs` | 撮影用のデモデータ（ローカルの D1 用）を SQL にする |
| `capture.mjs` | `video/shots/` の画面を撮り直す |
| `render.mjs` | MP4 を書き出す。静止画や曲だけの書き出しもできる |

## 動画の中身

120 BPM（1拍0.5秒）で、場面の切り替えと動きは拍に合わせてある。

| 秒 | 場面 | 字幕・見出し |
|---|---|---|
| 0–2 | コマが落ちてきて、問いかけが出る | 今度いつ集まれる？ |
| 2–6 | 6人分の時間割・スクショ・吹き出しが次々に積み重なって散らかる。5.5秒で全部が真ん中に吸い込まれる | 時間割を見比べても ／ 決まらない |
| 6–10 | ロゴ。朱と藍の四角が重なり、名前とキャッチコピーを読める長さで止める。重なりに飛び込んで次へ | コマあわせ ／ 友だちと、時間割を共有しよう。 |
| 10–14 | 4人の時間割が立体的に重なって「コマを重ねる」画面になり、空きコマが光る | 重ねるだけで ／ みんなの空きコマがわかる |
| 14–18 | 授業をさがす画面から授業を選ぶ。スクショが読み込まれて時間割に入る | 授業は選ぶだけで入る（シラバスやみんなの登録から選べる） ／ スクショからまとめて読み込める |
| 18–22 | 今の授業へスマホごと寄る。通知が届く。予定タブ | 今の授業がひと目でわかる ／ 授業の前に通知が届く ／ 課題と予定もまとめて見られる |
| 22–26 | 機能を1つ1秒で4つ。最後は書き出した画像がスマホから飛び出す | メモ・資料・課題 ／ 休講もすぐわかる ／ サークルやゼミで ／ 画像で保存・共有 |
| 26–30 | エンド | コマあわせ ／ 友だちと、時間割を共有しよう。 ／ koma.tomakura.com |

見た目は [docs/design.md](../docs/design.md) と同じ。生成りの地、墨の文字、朱と藍、Zen Maru Gothic・Zen Kaku Gothic New を使い、動きのモチーフは角丸の四角（コマ）にしている。

### 曲

ライブラリや音源ファイルは使わず、Web Audio API だけで鳴らすオリジナル曲。`buildMusic` は、再生用の `AudioContext` と書き出し用の `OfflineAudioContext` の両方に同じ音を組むので、映像と音がずれない。

- F メジャー。マリンバ・鉄琴・エレピ・ベース・パッド・キック・クラップ・ハイハット（ノイズから作る）
- 出だしは学校のチャイム（ウェストミンスターの鐘。パブリックドメイン）をマリンバと鉄琴で鳴らす。22〜26秒の機能紹介では、同じチャイムを1つの機能に2音ずつ鳴らす
- 10秒からがサビ（IVmaj7 – V7 – iii7 – vi7）。物が落ちる・飛び込む・通知が届くところには効果音を当てている
- 残響は作ったインパルス応答、最後にコンプレッサーで音量をそろえる

### これまでの直しで決めたこと

あとで直すときに戻さないように残しておく。

- 「無料・広告なし」は主張しない。プライバシー（見せる相手を選べる）の場面と、ダークモードの紹介は入れない
- 機能紹介は詰め込まない。1つ1秒で4つまで。見出しは次が出る前に下げきって、重ねない
- 画面に寄るときは、中の画像ではなくスマホの枠ごと拡大する
- 書き出した画像は、スマホの中ではなく画像として飛び出させる
- 「決まらない」場面は、ちゃんと散らかって見えるくらいに物を重ねる
- ロゴは止めて読ませる。四角は最初から重なる位置へまっすぐ入れ、意味のない揺れや背景の動きは付けない
- 字幕は「〜、〜。」の体言止めや「…」を使わず、ふつうの言い方にする
- 鉄琴は倍音のそろった素直な音にする（ずらした倍音や矩形波は変な音に聞こえた）

## 作り方

Playwright（`npm i --no-save playwright` と、その Chromium。または `CHROME` に Chrome のパス）と FFmpeg（PATH にあるか、`FFMPEG` にパス）が要る。書き出したものは `promo/out/` に出る。

### 画面を撮り直すとき

1. デモデータをローカルの D1 に入れる。ID がすべて `dm-` で始まる架空のデータ（みなと大学、あおい・ゆい・そうた・りん など）で、入れ直すと前のデモデータは消える
   ```sh
   npm run db:migrate:local
   node promo/seed.mjs
   npx wrangler d1 execute DB --local --file promo/out/seed.sql
   ```
2. `npm run dev` を 5173 番で動かして撮る。時刻は 2026年10月1日（木）13:25 に固定して、今日の列と3限の授業中が出るようにしている。ログインはデモデータに入っている固定のセッション（ローカル専用）を使う
   ```sh
   node promo/capture.mjs            # 全部
   node promo/capture.mjs export     # 1枚だけ
   ```

### MP4 を書き出すとき

```sh
node promo/render.mjs v              # 縦 1080×1920 → promo/out/komaawase-30s-9x16.mp4
node promo/render.mjs h              # 横 1920×1080 → promo/out/komaawase-30s-16x9.mp4
node promo/render.mjs v peek 3 10.5  # その秒の静止画だけ（構図の確認用）
node promo/render.mjs v audio-only   # 曲だけ（promo/out/music.wav）
```

1本あたり数分かかる。30fps・30秒・H.264（CRF 17）・AAC 256kbps。

## 撮影について

- 画面はすべて実際のアプリを、ローカルの開発サーバーとデモデータで撮った。大学・人・授業・先生の名前はどれも架空
- `video/shots/` は 2026年10月1日の画面。`export.webp`（画像で書き出す画面）だけ 2026年10月21日に撮り直した
