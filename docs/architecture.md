# 技術スタックと仕組み

## 方針

軽くて速いことを優先する。Cloudflare の無料枠の中で動かせる構成にする。

## 技術スタック

| 役割 | 使うもの |
|---|---|
| 画面 | SvelteKit（Svelte 5）＋ `@sveltejs/adapter-cloudflare` |
| 実行環境 | Cloudflare Workers（静的アセット配信付き）。Pages ではなく Workers にする |
| データベース | D1 ＋ Drizzle ORM |
| ファイル | 資料はシンレンタルサーバー（`relay/files.php`）。R2 は無料枠でもカードの登録が要るので使わない |
| 順番待ち | Queues（`koma-import` と通知の `koma-push`。無料プランは1日10,000操作、保持は24時間） |
| 定期実行 | Cron Triggers（毎日 10:00 JST：スクショの再挑戦、後片付け、運営の数字の記録。1分ごと：授業の前の通知と、前の日の20時の通知） |
| スクショ読み取り | Groq（`qwen/qwen3.8-27b`）、予備に Workers AI（`@cf/meta/llama-4-scout-17b-16e-instruct`） |
| パスキー | SimpleWebAuthn |
| Google ログイン | arctic |
| PWA | SvelteKit の Service Worker（`src/service-worker.ts`）とマニフェスト |
| CSS | 素の CSS ＋ CSS 変数 |
| フォント | `@fontsource/zen-kaku-gothic-new`・`@fontsource/zen-maru-gothic`（自分のサイトから配る） |
| お問い合わせのボット対策 | Cloudflare Turnstile（キーがなければ使わない） |
| 授業名の改行 | `Intl.Segmenter`（ブラウザと Workers に最初から入っている） |
| 画像書き出し | ブラウザの Canvas 2D |
| QR コード | uqr（依存なし） |
| テスト | Vitest（計算の部分だけ。`src/lib/*.test.ts`） |

## Worker のエントリーポイント

`@sveltejs/adapter-cloudflare` は `fetch` だけの Worker を、Wrangler の設定の `main` に書き出す。順番待ち（`queue`）と定期実行（`scheduled`）も受けたいので、次のように分けている。

- アダプターは `svelte-kit.wrangler.jsonc` を読み、`.svelte-kit/cloudflare/_worker.js` に書き出す
- デプロイと `wrangler dev` は `wrangler.jsonc` を読む。`main` は `worker/entry.js` で、SvelteKit の Worker を包んで `queue` と `scheduled` を足す
- `queue` と毎日の `scheduled` は、SvelteKit の `/internal/import` と `/internal/daily` を同じ Worker の中で呼ぶ（1分ごとの `scheduled` は SvelteKit を通さない。[授業の前の通知](#授業の前の通知)）。そのとき `env` に `KOMA_INTERNAL: true` を足して渡す。外からのリクエストの `env` にはこれがないので、`/internal` は外からは 404 になる
- `npm run dev`（Vite）では順番待ちの受け手が動かないので、アップロードした画像はその場で読み取る

## ログイン

- 登録：Google か、メールアドレス（確認リンクを送る）
- ログイン：おもにパスキーを使う。登録が終わったらパスキーを作ってもらう
- 予備：パスキーを失くしたときのために、メールでのログインを残す
- Google：arctic で PKCE を使う。Google の id で見つからなければ、Google が確認済みのメールアドレスでアカウントを探して結びつける（メールのリンクでも確かめたアドレスなので）。どちらもなければ作る。Google が確認していないアドレスは受け付けない。アドレスで探す・作るのは Gmail と Workspace（`hd` がある）のアカウントだけ。ほかのアドレスで作った Google アカウントは、そのアドレスが今も同じ人のものとは限らないので、メールのリンクでログインしてもらう。`GOOGLE_CLIENT_ID` と `GOOGLE_CLIENT_SECRET` を入れるまではボタンを出さない。リダイレクト先は `https://koma.tomakura.com/login/google/callback`
- ボタン：Google のブランドガイドラインに従い、色つきの G をライトは白、ダークは `#131314` のボタンに置く（モックの単色の G はガイドラインで禁止されている）
- ログイン後に戻る先：友だちリンクやグループの招待をログインしていない人が開いたときは、`next` の Cookie に覚えておき、メールのリンク・ニックネーム・パスキー・はじめの設定を終えたあとで開く。同じサイトのパスだけ受け付ける
- パスキーの候補：ログイン画面のメール欄は `autocomplete="username webauthn"` で、対応しているブラウザでは、画面を開いたときからパスキーを待つ。欄の候補から選ぶと、そのままログインする（`loginWithPasskey(true)`）。画面を離れるか、ほかのログインを始めたら待つのをやめる。取り消したときと、この端末にパスキーがないときはブラウザが同じ答えを返すので、どちらも「パスキーがないときは、下のメールでログインしてください」と出す。それ以外の失敗は「もう一度試すか、メールでログインしてください」と出す
- 在籍確認：大学のメールアドレスに確認リンクを送り、届いたらバッジを付ける。ドメインは大学ごとに `UNIVERSITIES.email_domains` に入れる（デジタルハリウッド大学は `dhw.ac.jp`）。判定は、許可したドメインと完全に一致するか、`.` 区切りのサブドメイン（例：`st.dhw.ac.jp`）のときだけ通す。ただの文字列の末尾一致だと `fakedhw.ac.jp` まで通ってしまうので使わない。大学名の表示には [Hipo/university-domains-list](https://github.com/Hipo/university-domains-list) を参考にできるが、古いデータも混じっているので判定には使わない。リンクを使えるのは、申し込んだアカウントでログインしているときだけ（`src/lib/server/verify.ts`）。ログインしていなければログイン画面を通ってから開き、別のアカウントでログインしていれば使わせず、ログアウトして入り直すよう案内する。開いた画面にどのアカウントのどのアドレスかを出し、「確認する」を押す（POST）まで使い切らない（メールのスキャナーが GET で開いても使い切らない）。そのアドレスがほかのアカウントの在籍確認に使われているときは、確認を移さずに断る（`taken`）。リンクが人の手に渡っても、ほかの人の確認を奪えないようにするため。
- メールは、シンレンタルサーバーに置いた中継用の PHP（`relay/send.php`）から送る。Workers からはシンの SMTP に接続できない（国外クラウドからの接続が遮断される）ため、Workers は HTTPS で中継に頼む。リクエストは共有鍵の HMAC で署名し、5分より古いものは断る。署名には1回きりの値（`x-koma-nonce`）も入れ、中継は使った値を覚えておいて、同じ署名の再送を断る（詳しくは[署名は1回だけ](#署名は1回だけ)）。中継が送れるのは決まった2つの文面（ログイン用・在籍確認用）だけで、それぞれコマあわせの決まったページへのリンクしか受け付けないので、ほかのメールの送信には使えない
- メールの数：ログインと在籍確認のメールは、次の順に止める（`src/lib/server/mail-limit.ts`、`auth/email.ts`、`verify.ts`）。数字は[回数制限](#回数制限)
  1. IP ごとの回数（Cloudflare の WAF）
  2. 同じアドレスに60秒あけずに送らない。ログインリンクは未使用が3つまで、在籍確認のリンクは1人3つまで
  3. アプリ全体で1時間500通・1日5,000通。レンタルサーバーは1時間1,500通・1日15,000通を大きく超えると、メールの送信が止まる。止まると全員のログインメールが届かなくなるので、その3分の1で止める。超えたら作ったリンクを消して「アプリ全体の上限に達しました」と出す（ログインの画面には、パスキーがあればパスキーでログインできる、と添える）
  - 全体の数は D1 の `rate_counts` に、1時間ごと・日本時間の1日ごとのキー（`mail:h:…`・`mail:d:…`）で持ち、1文で「上限に達していなければ1足す」。1時間の上限で止まった分は1日の数に入れない。期限が過ぎた行は毎日の Cron で消す
  - 送る画面（`MailSent`）は「もう一度送る」を60秒後から押せるようにし、「別のアドレスにする」で入力に戻れる。送れなかったときも入力したアドレスは残す
- もう一度ログイン（`src/lib/server/auth/reauth.ts`）：退会と運営の画面は、ログインし直してから開く。ログイン画面に `?reauth=delete`・`?reauth=admin` を付けて送り、「退会する前に、もう一度ログインしてください。」のように理由を出す。すでにログインしていても、この画面は開く。パスキー・Google・メールのどれでもよく、終わると `sessions.authed_at` が新しくなる
  - 退会：「その他」の退会のリンクは毎回ログイン画面を通る。退会の画面はログインし直して10分以内だけ開け、消す操作は30分以内
  - 運営（`/admin` とその下の画面・共有授業の運営の操作）：開くとき10分以内にログインしていなければ求める。使っているあいだは延ばし（`authed_at` を1分より古ければ更新）、10分使わないとまた求める。運営でない人には 404
  - ログインし直すと、前のログインは終わる。同じ人なら通知の宛先は新しいログインに移り、別の人なら消える（`signIn`）
- ログイン中の端末（`/more/sessions`）：有効なログインを、端末の名前（「iPhone・Safari」のように OS とブラウザ。機種名は取らない。`src/lib/device.ts`）と最後に使った日で並べ、この端末を先頭にする。ほかの端末は1つずつ、またはまとめてログアウトさせられる。この端末のログアウトは「ログアウト」から。パスキーを消したあと、ほかにログイン中の端末があれば、この端末のほかをすべてログアウトするか聞く（どのパスキーでログインしたかは記録していないため）
- 利用停止：運営が止めた人（`users.suspended_at`）は、止めたときにすべてのログインと通知の宛先を消す（`suspendUser`、`src/lib/server/moderation.ts`）。そのあとは、パスキー・Google・メールのリンクのどれでもログインを断り、「このアカウントは、利用が制限されています。」と出す。万一ログインが残っていても、`validateSession` が見つけたときに消す
- ログアウトと通知：通知の宛先（`push_subscriptions`）にはオンにしたときのログイン（`session_id`）を持たせる。ログアウトの操作は、この端末の宛先（endpoint）もサーバーに送って消させ、ブラウザ側の登録も外す。ログインが終わると（ほかの端末から外したときも）、そのログインでオンにした宛先が消える。`session_id` を持つ前の宛先は、ログアウトしても消えない

## スクショ読み取り

ほかのアプリの時間割のスクショを、画像を読める AI で JSON に変換する。

### 使う AI

どちらも、無料枠でもデータを学習に使わないサービス。

| 順番 | サービス | モデル | 無料枠 | 目安 |
|---|---|---|---|---|
| 1 | Groq | `qwen/qwen3.8-27b` | 1日1,000回、1分8,000トークン、1日200,000トークン | 1日50件くらい |
| 2 | Workers AI | `@cf/meta/llama-4-scout-17b-16e-instruct` | 1日10,000 Neurons | 1日60件くらい |

- AI には授業ごとに曜日を答えさせず、表を行ごと・マスごとに書き写させる（`days` と `rows[].cells`）。曜日と時限は見出しからこちらで決め、上下に続く同じ授業は1つにまとめる。授業ごとに曜日を答えさせたら、実際のスクショで列を取り違えた（月曜が木曜になり、授業も抜けた）ため。プロンプトは短いまま保つ（1行足しただけで漢字が化けた）
- 表を丸ごと読ませると、どちらの AI も列を数え違えた（水曜の授業が木曜になり、警告も出ない）。授業の少ない列をまたぐと起きやすく、実際のスクショで Groq は 12マス中5マス、Scout も数マスずれた。そこでブラウザ側（`src/lib/import-grid.ts`、`import-tiles.ts`）で表を見つけ、授業の入っているマスと曜日の見出しだけを切り出して、左に札（`B3` = 左から2列目・上から3行目、見出しは `B0`）を付けて縦に並べた1枚にして送る（ジョブの `tiled`）。列と行はこちらで札から決めるので、ずれようがない。同じスクショで Groq も Scout も全マス正しく、文字が大きくなって誤読も減り、出力トークンは半分ほどで済んだ（`IMPORT_TILE_PROMPT` と `IMPORT_TILE_SCHEMA`、読み取りは `readImport` の `cellsOfTiles`）
- 表の見つけ方は、マスの間を縦横に走る同じ色の帯（罫線、またはカードの隙間）。列の半分以上がその色なら区切りとみなし、規則正しくマスを切れる色を選ぶ。罫線が細くなまっていると2段階目の許容で探す。マスの並びが不規則・区切りの抜け・列や行が3つ未満のときは表とみなさず、従来どおり丸ごと送る（間違った列で切るより、丸ごとのほうがよい）。罫線が長辺2000pxより縮んだ画像は今のところ見つけられない
- 罫線もカードの隙間もない画面、結合セル（2コマ続きの1枚カードで、文字が上のマスだけにあるもの）、時限の番号が1から始まらない表は、まだ試していない。時限は表の上から数えた行番号にしている
- どちらにも同じ JSON Schema（`src/lib/import.ts` の `IMPORT_SCHEMA`）で返させる。Groq は `strict` で、考える過程は出させない（`reasoning_effort: "none"`）
- Groq の画像は1枚2,048トークン。指示文と出力を足して1回3,000〜4,000トークンくらい。1分の上限にかかる（429 で待ち時間が2分以内）ときは、その時間だけ待って Groq でやり直す。1日の上限なら Workers AI に回す
- Workers AI の Llama 4 Scout は画像と JSON Schema に対応していて、Llama 3.2 Vision のような利用規約の同意のリクエストが要らない。手元で自分の時間割の画像を読ませ、授業名・曜日・時限・教室まで正しく読めた
- Groq はダッシュボードの Data Controls でゼロデータ保持（ZDR）を有効にして使う。本番の前に有効になっていることを確認する。鍵は Worker の secret `GROQ_API_KEY`。ないときは Workers AI だけで読む
- 使わないもの：Mistral の無料枠（評価・試作用で、初期設定だと学習に使われる）、GitHub Models（試作用で本番利用は規約違反）、Gemini と OpenAI の無料枠（学習に使われる）

### 流れ

1. ユーザーが、「読み込む前に」の注意書き（画像が外部のサービスへ送られることを含む）を確認してチェックを入れ、スクショを切り抜いて送る。チェックがない（`agreed` が true でない）アップロードは 403 で断る。はじめて送ったときに、確認した時刻を残す（`users.import_consent_at`）。ブラウザで長い辺1600px の JPEG の data URL にするので、Worker は変換に CPU を使わない。表が見つかれば、授業のマスを切り出して並べ直した画像にする（上の「表を丸ごと読ませると…」）
2. `IMPORT_JOBS` に画像ごとジョブを作ってから、Queues にジョブの id だけを積む
3. 受け手は1件ずつ（`max_concurrency: 1`）。ジョブを `processing` にしてから読む（同じメッセージが2回来ても1回だけ読む）
4. Groq で読む。枠切れ・エラー・結果が JSON Schema に合わないときは Workers AI に回す
5. 読めたら結果を保存して画像を消す。両方ダメなら「翌日に再挑戦」にして、「明日もう一度読み取ります」と伝える。3回だめなら「失敗」にして画像を消し、手入力を案内する
6. ユーザーが結果を確認・修正して保存する（授業の登録と同じ確かめ方を通す）

### 翌日に回したジョブ

Queues のメッセージは24時間で消えるので、再挑戦は Queues に頼らない。

- 元のデータは `IMPORT_JOBS` にある
- 毎日 10:00 JST の Cron Triggers で、「翌日に再挑戦」のジョブと、1時間以上止まっているジョブを Queues に積み直す。Groq も Workers AI も無料枠は 00:00 UTC（日本時間 9:00）に戻るので、その1時間あとに合わせている（戻るのが遅れる日があるため）（以前の 03:00 では戻る前に再挑戦して、3回の試行を使い切りかねなかった）
- 全員あわせて1日 `TOTAL_DAILY_LIMIT`（100件）まで。待っている・読んでいる件数と、9:00 以降に読み終えた件数を数え、上限なら画像は受け付けるがキューには入れず、「再挑戦」にして翌朝 10:00 に読む。その朝の分（100件）も予約で埋まっていれば、その次の朝にする（`quotaUsed`・`readSlot`、`src/lib/import-quota.ts`）
- 3日たっても読めなかったジョブは「失敗」にして画像を消す。30日たったジョブの行も消す
- ついでに期限の過ぎたセッション・ログイン用リンク・パスキーの確認用の値・アプリ全体の回数の記録（`rate_counts`）を消す
- 最後に、運営の「利用の状況」のために、その日の登録者数・24時間と7日に開いた人・在籍確認している人を `daily_stats` に1行書く（`recordDailyStats`、`src/lib/server/stats.ts`）。開いた人は `sessions.last_used_at` からしかわからず、あとから過去の日を数え直せないため

### 画像を消す範囲

| 場所 | 扱い |
|---|---|
| D1 の `IMPORT_JOBS.image` | 読み取りが終わったらすぐ消す。失敗しても3日で消す。消したあとも D1 の Time Travel（無料プランは7日）には残る |
| Groq | ZDR を有効にして使う（上記） |
| Workers AI | Cloudflare は入力と出力を保存しない |

注意書きでは「学習に使われない」と「保存されない」を分けて書く。

### 限界

AI の読み取りは間違えることがある。画面と規約の両方で、保存前に見直すよう明記する。

## 資料のファイル

授業の資料（PDF・写真・Word・PowerPoint・Excel）は、シンレンタルサーバーに置いた `relay/files.php` に保存する。R2 は無料枠でもカードの登録が要るため、すでに契約しているシンを使う。

- ブラウザは `files.php` に直接アクセスしない。Worker がログインと授業の持ち主を確かめてから、HMAC で署名したリクエストで保存・取り出し・削除を頼む。署名は5分で切れる。鍵はメール中継とは別（`FILES_SECRET`）
- ファイルは `public_html` の外に、Worker が決めたランダムな32文字の名前で置く。元の名前と種類は D1 の `course_files` に持つ
- 写真はブラウザで長い辺2000px の JPEG に縮めてから送る（HEIC も変換する）。送るときは multipart ではなくファイルそのものを本文にして、無料プランの CPU 時間に収める
- 1ファイル 10MB、1人の合計 100MB まで
- 本文は届くそばから読み、10MB を超えたところで読むのをやめて断る（`src/lib/server/body.ts` の `readLimited`）。`Content-Length` がない、または偽っている本文を、まるごとメモリに置かないため。`Content-Length` が大きすぎるものは、読む前に断る
- 100MB の上限は、資料の行を足す1つの文の中で数える（今の合計＋このファイルが上限以内のときだけ足す）。同時に送られても、合計が超えない。足せなかったときは、先にシンレンタルサーバーに置いたファイルを消す
- 見せるときも Worker を通す。`nosniff` と `Content-Security-Policy: sandbox` を付け、ページのスクリプトを動かせない種類しか受け付けない。PDF だけは sandbox を付けない（ブラウザの PDF ビューアが動かなくなるため。PDF の中のスクリプトはビューアの中でしか動かない）
- 資料や授業を消すときは、先にシンのファイルを消す。消せなかったら授業も消さず、だれにも見えないファイルが残らないようにする
- 無料プランの Worker は、1回のリクエストで外部へのリクエストを50回までしか出せない。退会でファイルを消すときは40件ずつにして、残りがあれば画面がもう一度送る

### 署名は1回だけ

メール中継（`send.php`）も資料の保存（`files.php`）も、Worker が署名したリクエストしか受けない。5分の期限に加えて、盗み見た通信をそのまま送り直しても通らないようにしている。

- Worker は、リクエストごとに新しいランダムな32文字（`x-koma-nonce`）を作り、署名に入れる（メールは `<時刻>.<nonce>.<本文>`、資料は `<時刻>.<nonce>.<操作>.<キー>.<大きさ>.<sha256>`）
- `send.php` と `files.php` は、署名が合ったあとにその値をシンの `koma-nonces/`（`public_html` の外）に1ファイルとして記録し、同じ値がもう一度来たら断る（`used`）。ファイルを作れるのは1回だけなので、同時に2つ来ても1つしか通らない
- 記録は、その値の時刻が5分の許容の外に出るまで持つ（11分）。ときどき古いものを消す。手で消してもよい
- 資料の保存の署名には、ファイルの SHA-256 も入る。保存の直前に中身を計り直して、合わなければ断る（`hash mismatch`）。署名を別の中身につけ替えられない
- Worker と PHP は同じ版でないと通らない。**公開のときは `send.php` と `files.php` の両方をシンに上書きする**（手順は [relay/README.md](../relay/README.md)）。片方が古いあいだは、ログインのメールか資料の保存が失敗する

## オフライン（PWA）

- `static/manifest.webmanifest` とアイコン（`scripts/make-icons.mjs` でロゴから作る）で、ホーム画面に追加できる
- Service Worker は、ビルドしたファイルと `static/` を最初に保存し、ページと `__data.json` はネットワークを先に見て、つながらないときに最後に見たものを出す。フォント（`.woff2`）だけは最初に保存せず、ページが使ったときに取って残す（`keepFont`。文字の範囲ごとに分かれた小さいファイルが何百もあり、ほとんどのページは使わないため）。一度使ったフォントは、オフラインでも出る
- ログイン・ログアウト・認証・アップロード・資料・データの書き出し・`/internal`・運営画面は保存しない。保存したページは、SvelteKit の `x-sveltekit-invalidated` 以外のクエリまで一致するときだけ出す
- 残したページには時間割が入っているので、ログイン画面を開いたとき（ログアウト・退会のあと）に消す。バージョンが変わると古いものも消す

### つながらない・遅いとき

つながらないだけでなく、返事が来ないことが多い（`fetch` が失敗せず止まる）。そこで保存したコピーがあるページは、ネットワークに `SLOW_MS`（4秒）だけ待ち、間に合わなければコピーを出す。ネットワークへの要求はそのまま続け、返ってきたらコピーを置き換える。コピーがなければ待ち続ける。

- 取得時刻：コピーは `x-koma-saved-at`（保存した時刻）を付けて保存し、出すときも付けたまま返す。ページそのもの（HTML）は自分のヘッダーを読めないので、コピーで開くときは Service Worker が `<html data-cached-at="…">` を足す。画面はこれで「いつの情報か」を知る
- 取れなかったページの代わり：ネットワークが失敗した（つながらない）ページは、同じページの、クエリなしのコピーがあればそれを出す（`nearKey`。データの要求は SvelteKit の `x-sveltekit-trailing-slash` だけ残す）。遅いだけのときは代わりを出さず、待つ。何もなければ全画面の「つながっていません」ページを出し、「もう一度開く」と「時間割へ」を付ける（SvelteKit は、データが取れないと全画面の読み込みに切り替えるので、保存していない要求はここへ落ちる）
- 待つ間の画面：ページ（HTML）を開くとき、ネットワークが `GRACE_MS`（0.7秒）で答えなければ、Service Worker は中央にぐるぐるを出すだけの殻（`src/lib/wait.ts` の `waitShell`）をすぐ返し、そのあとに本物のページを同じ文書へ続けて流す（`TransformStream`）。ブラウザは2つめの `<!doctype>` を捨て、2つめの `<html>` `<body>` の属性を最初のものに足すので、`data-theme` や `data-cached-at` も届く。ぐるぐるは、続きがすべて届いたあとの `<script>`（`WAIT_DONE`）が消す（CSS の読み込みを待つので、スタイルなしの画面は見えない）。届かなければ30秒で消える。保存コピーがあれば4秒（`SLOW_MS`）までネットワークを待ってからコピーを流す。リダイレクトは流れに乗せられない（`opaqueredirect` は行き先が読めない）ので、もう一度たずねて行き先を知り、`location.replace` で移る。速く答えたときはこれまでどおりそのまま返す（リダイレクトもそのまま）。アプリの中の遷移は `NavigationWait.svelte` が `navigating` を見て、0.4秒たってから出す
- 接続の状態（`src/lib/connection.svelte.ts`）：`online` / `poor`（返事が遅い・コピーで開いた） / `offline`（つながらない・端末がそう言っている）。`poor` と `offline` の間は `<html data-offline>` を付け、リンクの先読み（`data-sveltekit-preload-data`）を止める。帯は `ConnectionBar.svelte`
- 確かめる：`/api/ping`（`hooks.server.ts` で D1 もセッションも読む前に 204 を返す）に6秒で返事があるか。ないなら `poor`、要求が出せないなら `offline`。つながったら同期してから、画面を読み込み直す（`refreshAll`）。失敗が続くほど間を空けて再挑戦する（5秒・10秒・20秒・30秒、以降は1分おき）。端末の `online` イベントと、アプリを開き直したときも試す
- 同期（`src/lib/sync.ts`）：下の4タブのデータを順に取り、進み具合を帯に出す。通信を減らすため、要求ごとに最後に取れた時刻を端末に持ち（`koma:fresh`、アプリのバージョンつき）、新しいものは飛ばす（`dueSteps`）。時間割は15分、ほかのタブは3時間（開いて取れたものと、開いたページのHTMLも数える）。コピーが消えている（新しいバージョンで消える）ものは、時刻が新しくても取り直す。Service Worker がまだページを制御していないとき（初めて開いたとき）は、答えが保存されないので取れたことにしない。データ節約中は時間割だけ。更新ボタンは全部取り直す。変更のあとは、その後に取れていない時間割だけ取り直し（6秒待ってまとめて）、重ねる・その他は記録から外して次の同期で取り直す（自分の時間割や学期・時限を使うため）。要求には `x-koma-sync` を付ける。Service Worker はこれを見て、コピーには逃げずネットワークの答えだけを返して保存する（本当にサーバーが答えたか分かるように）。最初に失敗した時点でやめる（悪い回線で続けても無駄なので）。時間割は HTML もいっしょに取る（冷えた状態で開くのは HTML なので）。ログアウトしていれば、データ要求の答えがリダイレクトになるので、それで分かる
- 使えなくするもの：`poor` と `offline` の間、次を止めて理由を出す（トースト）。
  - フォームの送信：`document` の `submit` を捕まえる段階（`capture`）で止める。約50あるフォームを1つずつ直さなくてよい
  - 変更を伴う `fetch`：`window.fetch` を包んで止める（資料のアップロードなど、フォームでないもの）
  - 遷移：`beforeNavigate` で止める。授業の追加・さがす・スクショ読み込み・友だち／グループの追加（`needsServer`）と、端末に保存していないページ。保存しているかは `copyKey`（パスと、表示を変えるクエリ。SvelteKit 自身のパラメータは除く）で見る。同じページの中でクエリだけが変わる遷移（重ねる画面の `?with=`）は、そのクエリのコピーがなければ止める。別の情報だからで、別のクエリのコピーを出すと、選んだ人とちがう画面になる。別のページへ移るときは、クエリ違いのコピーで足りる（`openableOffline`）。重ねる画面は、止めるときに選び方の状態と Cookie を変えないよう、遷移の前に `guardNavigation` を呼ぶ保存していないページに行くと、SvelteKit はデータが取れず全画面遷移して Service Worker の「つながっていません」ページに出てしまうため、手前で止める
- 帯の高さ：ページの最小高さ（`--page-h`）から帯の高さ（`--bar-h`）を引き、帯が出ても縦にスクロールしないようにする。上に貼りつくヘッダー（`CourseForm`）は `top: var(--bar-h)`
- 空きコマは `opacity` で薄くしない。`opacity` が 1 未満の要素は重なり順が前に出るので、隣の授業のマスに重なってしまう。枠だけにする（`TimetableGrid.svelte`）

## 戻る操作

ブラウザの戻る（ボタンもスワイプも）では、SvelteKit がそのページのデータ（`__data.json`）をサーバーから取り直し、届くまで画面が変わらない。そこで `window.fetch` を差し替えて（`src/lib/page-data.ts`）、戻るときだけ前に読んだコピーをすぐ返し、そのうしろでサーバーに聞いて、変わっていたら画面を更新する（`refreshAll`）。

- コピーを使うのは戻る・進む（`beforeNavigate` の `popstate`）で、同じページ・同じ `x-sveltekit-invalidated` のときだけ。リンクで開くときは、いつも通りサーバーに聞く
- GET・HEAD 以外のリクエストが出たら、コピーを全部捨てる。メモリの中だけなので、再読み込みやログアウトでも消える。リダイレクトや失敗の返事は残さない
- 最初に開いたページのデータは HTML の中にあってコピーがないので、タブ（`/`・`/overlay`・`/friends`・`/more`）だけ、開いて2秒後に1回読んでおく
- データに `now`（サーバーの時刻）が入っているページ（時間割・コマを重ねる）は、`now` が毎回変わり、画面が日付や時刻をそこから読む。そのため、コピーを見せるときは `now` を端末の時刻に差し替え、変わったかどうかを比べるときは `now` を除く
- 写真のアイコン（`/icons/<id>?v=…`）はブラウザに1日とっておくので、戻っても取り直さない（友だちをやめたあとも残らないよう、ずっとはとっておかない）。`UserIcon` の `<img>` には `loading="lazy"` と `decoding="async"` を付けない（作り直した画面で、写真だけ遅れて出るのを避ける）

## 授業を時間割の上に開く

時間割から授業を開くと、時間割を後ろに残したまま授業の画面を重ねる（SvelteKit の shallow routing）。閉じると、開く前の時間割（同じ学期）にそのまま戻る。

- ホーム（`src/routes/+page.svelte`）が、`/courses/<id>`（`new`・`search` を除く）へのリンクのクリックを先に受ける。修飾キーつき・別タブ・ダウンロードのリンクは、ふつうに開く
- `preloadData` で授業のデータを先に読み、取れたら `pushState` でアドレスを授業のものに変えて重ねる（`page.state.course`）。取れなかったときは、ふつうの遷移にする
- 重ねる画面も授業のページ（`/courses/[id]`）も、同じ部品（`src/lib/components/CourseDetail.svelte`）。アドレスは授業のものなので、再読み込みや共有したリンクは、授業のページとして開く
- 閉じるのは、ブラウザの戻る・後ろの暗い部分・下へのスワイプ・OS の戻る操作。どれも `history.back()` に集まる
- メモ・課題・資料を変えたあとは、授業だけを読み直す（同じアドレスに、毎回違うパラメータを付けて `preloadData` し、`replaceState` で入れ替える）。ページ全体を読み直す `invalidateAll` は、重ねた画面も閉じてしまう。授業のページとして開いているときは、これまでどおり `invalidateAll`
- アプリ全体の読み直し（アプリに戻ったとき、オンラインに復帰したとき、戻る操作のあとの更新）は `refreshAll` にしてある。`invalidateAll` と違い、重ねた画面を閉じない。時間割の読み直しで中身が変わったときは、重ねている授業も読み直す
- 重ねた画面のスクロールは `data-swipe-scroll` の箱が受ける。下へのスワイプで閉じられるのは、この箱が上端までスクロールしているとき（`src/lib/swipe.ts`）
- 授業の編集画面（`CourseForm`）は、変更したまま別の画面へ行こうとすると、「変更を保存していません。戻りますか？」を出す（`beforeNavigate`）。保存するとき、「戻る」を選んだあとは止めない。タブを閉じる・サイトを離れるときは、ブラウザ自身の確認になる

## 画面の動き

画面の切り替えは View Transitions で動かす（`src/routes/+layout.svelte` の `onNavigate`、CSS は `src/app.css`）。`<html data-nav="…">` の値で動きを決める。動きを減らす設定の端末と、同じパスの中の遷移（別の学期など）では動かさない。

| `data-nav` | いつ | 動き |
|---|---|---|
| `tab-right` / `tab-left` | 下のタブ（時間割・重ねる・友だち・その他）どうし。行き先が右のタブなら `tab-right` | 古い画面が左へ、新しい画面が右から（左のタブへは逆）。56px 動きながら消える・現れる。下のバーは動かない |
| `sheet-open` / `sheet-close` | 授業のページへ入る・出る（重ねずに開く場合） | 下からシートが上がり、下へ閉じる |
| `forward` / `back` | 奥の画面へ進む・戻る（パスの深さで決める） | 右から入り、右へ戻る |
| `fade` | ほかの遷移 | ふわっと切り替える |

- 送信のボタン（`SendButton.svelte`）：`phase`（`idle`・`sending`・`done`）で、ぐるぐる（`.wheel`）→ チェックマーク（線が描かれる）を出す。フォームを送るページは、成功したら `done` にして、`src/lib/send.ts` の `pauseAfterSent`（650ms。動きを減らす設定では0）を待ってから `update()` する。送ったあとの案内（`MailSent.svelte`、お問い合わせの完了）は `fly`（下から28px）で入る
- ロゴ（`Logo.svelte`）は、テーマの色（`--shu`・`--ai`）と `--logo-blend` で描くインラインの SVG。ログイン画面と `AuthScreen.svelte`（メールのリンクの画面）は、ロゴと名前を上に固定し、下の内容を下に置く
- 学期の印（`TermBar.svelte` の `.mark`）：選んだタブの後ろの地色を、タブの位置と幅（`offsetLeft`・`offsetWidth`）に合わせて動かす。最初に置いたあと（50ms後）から動かし、タブの大きさが変わったとき（フォントが届いたときなど）も置き直す。置くまでは、選んだタブ自身が地色を持つ
- マスの現れ方（`TimetableGrid.svelte` の `stagger`）：学期を切り替えたときだけ、マスが左上から順に現れる。マスごとに `--n`（行＋列）を持ち、1つにつき20ms ずつ遅らせて、0.3秒で不透明・大きさを戻す。開いたときの最初の表示では動かさない
- 「みんな空いてるコマ」の札（`src/routes/overlay/+page.svelte`）：出入りを1つずつ30ms ずらす（最大16番目まで）。動きを減らす設定では遅らせない

## 授業の前の通知

1分ごとの Cron（`wrangler.jsonc` の `* * * * *`）が `CLASS_REMINDERS` を読み、「今からその分数あとに始まる授業」がある人の端末へ送る。同じ Cron で、前の日20時の通知（`plan-eve.ts`）と、課題の締め切りの日の通知（`task-reminders.ts`：朝8時、締め切りの3時間前・1時間前。どれも最初はオフ）も送る。課題の締め切りは夜中もあるので、Cron は一日中動かす。人が決めた「通知を送らない時間」（`users.notify.quiet`）には、どの通知も送らず、後からまとめて送ることもしない

- 無料プランの CPU は1回10ms までなので、SvelteKit を起動しない。`worker/entry.js` の `scheduled` が Cron の文字列を見て、日次のほうは今まで通り `/internal/daily`、1分ごとのほうは `src/lib/server/reminders.ts` を直接呼ぶ。動くのは1本のクエリで、何もなければそこで終わる
- クエリ：今年度の時間割（`archived = 0`）→ その曜日の授業のコマ → 時限の開始時刻 − 選んだ分数 = いまの分、で絞り、その日の休講（`course_notes.kind = 'cancel'`）、休みの日（`calendar_entries.kind = 'off'`）、振替でほかの日に移した授業（`course_moves.from_date`）を除く。振替でその日に移ってきた授業は、別のクエリを `UNION ALL` でつないで拾う。学期の期間（`termIsOn`）と隔週（`meetsInWeek`）はあとで JS で見る。時限の開始は `8:40` でも `08:40` でも読める
- 相対 import だけにしてある（`entry.js` から直接読むため）。`src/lib/server/reminders.test.ts` は本物のマイグレーションを `node:sqlite` に流して、このクエリごと確かめる
- 1分に送るのは40件まで（無料プランの外へのリクエストは50回まで）。始業の時刻に集中して超えるほど人が増えたら、キューに分けて送る形に変える。送った数は Worker のログに出る（`class reminders: sent …`）
- 通知の `tag` は `class-<コマ>-<日付>-<分数>`。同じ通知が二重に届いても、端末では1つに置き換わる
- 人数が増えたときの負荷：毎分、通知を選んだ人 × その人の授業数ぶんの行を読む。1日あたり D1 の読み取り上限（無料 500万行）に近づく前に、時刻ごとの索引を持つ形に変える

## 前の日の20時の通知

授業の前の通知と同じ1分ごとの Cron で、`worker/entry.js` が `src/lib/server/plan-eve.ts` の `sendPlanEve` も呼ぶ。日本時間の 20:00〜20:09 のときだけ動き、ほかの分は何もせずに終わる。

- 明日が締め切りでまだ済んでいない課題（`course_notes`、今年度の時間割）と、明日のイベント（`events`）を1本のクエリで読み、通知の種類 `planEve` をオフにしていない人ごとにまとめる。文面は `src/lib/plan-eve.ts` の `eveMessage`
- 1分に外へ送れるリクエストに上限があるので、人を 20:00〜20:09 の10分に散らす（`eveSlot`。id から決めるので、毎日同じ分）。1分に送るのは40件まで
- 通知の `tag` は `plan-eve-<日付>`。二重に届いても端末では1つになる
- 授業の前の通知と同じく、相対 import だけにしてある

## 通知（Web Push）

- 知らせるのは、友だち申請が届いた・承認された、スクショの読み取りが終わった（読めなかった）、グループに人が参加した、作ったグループに参加の申請が届いた、グループへの参加が承認された、前の日の20時の課題と予定（[前の日の20時の通知](#前の日の20時の通知)）の7つ（`src/lib/notify.ts`）。「その他」→「通知」で端末ごとに受け取りを始め、種類ごとにオン・オフできる（`users.notify`、ないものはオン）
- グループの申請は、申請した人が初めて申請したとき、作った人に送る（`groupRequest`）。承認したときは、本人に送り（`groupApproved`）、作った人以外のメンバーには参加したときと同じ通知を送る（`groupJoin`）。断ったときは送らない
- お問い合わせが届いたときは、運営（`role` が `admin` の人）の端末に送る。種類のオン・オフには入れていない（テストの通知と同じ扱いで、宛先があれば送る）
- 送るのは Worker から直接。ライブラリは使わず WebCrypto で、中身をブラウザ向けに暗号化し（RFC 8291、aes128gcm）、VAPID の鍵で署名する（RFC 8292）。`src/lib/server/push.ts`。通知サービス（Apple・Google・Mozilla・Microsoft）には中身が読めない
- 宛先は `PUSH_SUBSCRIPTIONS`。ブラウザの通知サービス以外のアドレスは受け付けない（Worker にほかへ送らせないため）。404・410 が返った宛先は消す。宛先にはオンにしたときのログインを結びつけてあり、ログアウトすると止まる（[ログイン](#ログイン)の「ログアウトと通知」）
- 送るのはレスポンスのあと（`waitUntil`）。1回に送るのは40件まで（無料プランの外へのリクエストは50回まで）
- iPhone・iPad はホーム画面に追加したアプリからだけ受け取れるので、通知の画面から追加のしかた（`/install`）へ案内する
- 鍵は secret の `VAPID_PUBLIC_KEY` と `VAPID_PRIVATE_KEY`（`node scripts/make-vapid.mjs` で作って入れる）。ないあいだは通知の画面に「まだ使えません」と出す

## 速さ（Worker の CPU）

無料プランの目安は1回10ms。利用者が少ないうちは多くのリクエストが起きたばかりの isolate に当たるので、起動と最初の1回を軽くしている。

- サーバーでは ICU のデータを読み込むものを作らない。日本語の単語分け（`Intl.Segmenter` の word、8ms以上）は授業名の区切りに要るので、ブラウザで行う（`src/lib/title.ts`）。文字の区切り（grapheme、約9ms）は絵文字などがあるときだけ、日本語の並べ替え（`localeCompare(…, 'ja')`、約7ms）はかなの順に並べる軽い比較（`src/lib/sort.ts`）、日本時間は UTC+9 を足すだけ（`src/lib/time.ts`）
- パスキーのライブラリ（@simplewebauthn/server とその証明書ライブラリ、約600KB）はパスキーの API だけで読み込む。セッションのトークンの base64url は自前（`src/lib/server/base64url.ts`）
- drizzle のインスタンスは D1 のバインディングごとに1つ
- 測り方：`scripts/bench-worker.mjs`（wrangler が作るバンドルを Node で動かし、D1 は node:sqlite で置き換える）。手元の計測では、起きたばかりの isolate の最初の1回は 45〜50ms → 35〜40ms（Node 自体の分を含む）、読み込みは 52ms → 38ms、温まったあとは 1.5〜4ms

## 速さ（D1 を待つ回数）

D1 は APAC のどこかにあり、東京で動く Worker から1回問い合わせると約85ms待つ。ページの待ち時間は、D1 を順番に何回待つかでほぼ決まるので、多くのページで2回（ログインの確認と、ページのデータ）にしている。

- ログインの確認で、今年度の時間割もいっしょに読む（`locals.timetable`、GET のときだけ）。フォームの送信では読まない：アクションが時間割を変えたあと、同じリクエストでページの load が動くことがあるため
- 前の結果の id を使う問い合わせは、id をサブクエリにして同じ batch に入れる（時間割と同期中の共有授業、授業ページと学期・時限、重ねる相手の時間割）
- 在籍確認済みかは EXISTS の列で一覧といっしょに読む（`verifiedColumn`）
- 見てよいかの確認と、相手の id で読むものは並べて読み、確認が通ったときだけ返す
- batch の中では、JOIN で同じ名前の列（`id` など）があると drizzle が値を取り違える。batch に入れる問い合わせは1つの表から読むか、列名が重ならないようにする
- Smart Placement を有効にしている（`wrangler.jsonc` の `placement`）。Cloudflare が速くなると判断すれば Worker を D1 の近くで動かす。アクセスが少ないうちは動かないこともある

## 回数制限

| どこで | 何を | 上限 |
|---|---|---|
| Cloudflare WAF（Rate limiting rules） | `koma.tomakura.com` への `POST /login` と `POST /api/passkey/login/options` | IP ごとに10秒で10回。超えたら10秒ブロック（429） |
| D1 | 同じメールアドレスへのログインリンク | 60秒に1通。未使用のもの（15分で切れる）は3つまで |
| D1 | 在籍確認のリンク | 1人3つまで（1日で切れる）。同じアドレスへは、だれが申し込んでも60秒に1通 |
| D1（`rate_counts`） | ログインと在籍確認のメール（全員あわせて） | 1時間に500通、1日に5,000通（日本時間の0時に戻る）。超えたら送らず、作ったリンクを消す。レンタルサーバーが送信を止める目安（1時間1,500通・1日15,000通）の3分の1 |
| D1 | お問い合わせ | 直近24時間で、全体で50件、1つのアドレスで3件 |
| D1 | スクショの読み取り | 1人1日5回、読み取り中は2件まで |
| D1 | 返事を待っている友だち申請 | 1人30件まで |
| D1 | 不具合・要望 | 1人1日10件まで |
| Workers の Rate Limiting バインディング | 上と同じ画面（IP ごと）と在籍確認のメール | 設定はしているが、本番では動いていなかった（同じ IP・拠点から25回送っても全部 success）。WAF のルールで代わりに守っている |

WAF のルールはダッシュボードで設定していて、リポジトリには入っていない。条件式は次のとおり。ルールに止められると Cloudflare の HTML が返るので、メールのフォームはそれを受けて「しばらく待ってから」と出す。

```text
(http.host eq "koma.tomakura.com" and http.request.uri.path in {"/api/passkey/login/options" "/login"} and http.request.method eq "POST")
```

## 休講の共有

同期している授業で、ほかの人が入れた休講を人数で見せる（`src/lib/server/cancellations.ts` の `sharedCancellations`）。

- 数えるのは、同じ共有授業を `synced` で入れていて、その大学の在籍確認が切れていない人。`share_cancellations` をオフにした人・利用停止の人・自分は数えない。運営が消した日（`cancellation_hides`）も数えない。今日から先の日だけ
- だれが入れたかは返さない。人数だけ
- 時間割のコマの「休講かも」は2人から（`MAYBE_MIN`、`src/lib/cancellations.ts`）。1人だけの日は授業の詳細にだけ出す。自分で休講を入れた日は出さない
- 友だちの時間割と画像の書き出しには入れない
- 報告は `reports` に `target_type = 'shared_cancel'` で入る（1人1日1件）。運営が消すと、その日への報告もまとめて対応済みになる（`hideCancellation`）

## 運営の警告と利用停止

- 警告（`warnings`）は、ルートのレイアウトが毎回、まだ押していない警告を1つ読む（`pendingWarning`）。あれば `WarningScreen.svelte` を画面いっぱいに出し、後ろの画面は `inert` にして触れなくする。「理解しました」は10秒たつまで押せず、押すと `/api/warning` が `acknowledged_at` を入れる
- 利用停止は[ログイン](#ログイン)の「利用停止」。止めた人は、友だちの一覧・グループのメンバー・休講の人数から外す（`suspendedIds`・`isNull(users.suspendedAt)`）

## データの書き出し

「その他」→「データの書き出し」は `/more/data`（GET）が、本人のデータを1つの JSON にして `attachment` で返す（`src/lib/server/data-export.ts`）。アカウント、時間割（学期・時限・授業・曜日時限・先生）、メモ・課題・休講、資料の一覧、欠席、イベント、友だち、グループが入る。資料のファイルの中身は入れない。Service Worker は保存しない（`src/service-worker.ts` の `NETWORK_ONLY`）

## お問い合わせ（`/contact`）

ログインしていなくても送れる。退会した人や、登録していない人も運営に連絡できるようにするため（プライバシーポリシーの連絡先でもある）。名前（50文字まで）・メールアドレス・内容（2,000文字まで）を受ける。ログインしていれば、ニックネームとメールアドレスを初めから入れる。返信は、入力されたアドレスに運営が送る。

- ボット対策は3つ：人には見えない入力欄（`website`。入っていたら、送れたように見せて捨てる）、Cloudflare Turnstile、件数の制限
- Turnstile：画面が開いたあとにウィジェットを描き（`api.js?render=explicit`）、送られたトークンを Worker が `siteverify` で確かめる（`src/lib/server/turnstile.ts`）。トークンは1回きりなので、送れなかったときは新しく取る。`TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET_KEY` の両方があるときだけ使う
- 件数の制限は、数えるのと足すのを1つの文にして、同時に送られても超えないようにしている。上限は[回数制限](#回数制限)
- 運営の画面（`/admin`）の「問い合わせ」に、未対応のものを新しい順に50件ずつ出す。メールアドレスから返信でき、「対応済み」で一覧から外れる（`contact_messages.status`）。未対応の件数は、「その他」の運営の行に、通報・不具合・要望と足して出る
- 届くと運営の端末に通知する

## セキュリティのヘッダーと CSP

- 応答には、`hooks.server.ts` で次のヘッダーを付ける（`/api/ping` の204は除く）：`X-Frame-Options: DENY`（ほかのサイトの枠に入れない）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Strict-Transport-Security`（1年）、`Permissions-Policy`（カメラ・マイク・位置情報・支払い・USB を使わない）
- ページの Content-Security-Policy は SvelteKit が付ける（`vite.config.ts` の `kit.csp`、`mode: 'auto'`）。SvelteKit 自身のインラインのスクリプトには nonce が付く
  - スクリプトは自分のサイトと、お問い合わせの Turnstile（`challenges.cloudflare.com`）だけ。Turnstile の枠（`frame-src`）も同じ
  - 画像は自分のサイトと `data:`・`blob:`。通信（`connect-src`）・フォント・Service Worker・マニフェストは自分のサイトだけ
  - スタイルはインラインを許す（Svelte のトランジションが `style` を書くため）
  - `object-src 'none'`、`base-uri`・`form-action` は自分のサイト、`frame-ancestors 'none'`
- 資料を見せる応答には、これとは別に `Content-Security-Policy: sandbox` を付ける（[資料のファイル](#資料のファイル)）

## フォント

- Zen Kaku Gothic New（400・500・700）と Zen Maru Gothic（500・700）は `@fontsource` から入れ、自分のサイトから配る（`src/routes/+layout.svelte` で CSS を読み込む）。ページを開くときに Google のサーバーへつながらない
- 文字の範囲ごとに分かれた小さいファイルで、ページに出る文字のぶんだけ読み込む
- 形式は woff2 だけ。Fontsource の CSS は woff も並べているが、対応するブラウザはどれも woff2 を読めるので、ビルドで woff の指定を外す（`vite.config.ts` の `woff2Only`）
- Service Worker は、フォントを最初には保存せず、ページが使ったときに保存する（「オフライン（PWA）」の節）

## プライバシー

- 時間割は初期状態で非公開。承認した友だちと、見せると選んだグループだけに見える
- 時間割は「いつどこにいるか」がわかる情報なので、書き出し画像では教室名を初期状態で入れない
- スクショは読み取り後に削除する（範囲は[画像を消す範囲](#画像を消す範囲)）。読み込む前に、画像を外部のサービスへ送ることを含む注意書きを確認してもらい、はじめて送ったときの時刻を持つ（`users.import_consent_at`）
- ログインの記録（`sessions`）には、「ログイン中の端末」に端末の名前を出すために、ブラウザの種類（User-Agent）と、ログインした日時・最後に使った日時を持つ。ログアウトか期限（最後に使ってから最長30日）で消す
- お問い合わせは、名前・メールアドレス・内容を、アカウントとつなげずに持つ。退会しても残る
- 資料は本人しか見られない。友だちやグループにも見せない。ファイルはシンレンタルサーバー（国内）に置く
- メモ・課題・休講・欠席・イベントは友だちにも見せない（友だちの時間割の画面や書き出しには入れない）。休講は、同じ授業を同期している人にだけ、だれかは出さずに人数で見せる（オフにできる）
- 運営の利用者の画面には、時間割の中身を出さない
- 本人は、自分のデータを JSON で書き出せる
- 退会時の扱いは [data-model.md](data-model.md#退会したとき)
