# 技術スタックと仕組み

## 方針

軽くて速いことを優先する。Cloudflare の無料枠の中で動かせる構成にする。

## 技術スタック

| 役割 | 使うもの |
|---|---|
| 画面 | SvelteKit（Svelte 5）＋ `@sveltejs/adapter-cloudflare` |
| 実行環境 | Cloudflare Workers（静的アセット配信付き）。Pages ではなく Workers にする |
| データベース | D1 ＋ Drizzle ORM |
| ファイル | R2（資料、読み取り待ちのスクショ） |
| 順番待ち | Queues（無料プランは1日10,000操作、保持は24時間） |
| 定期実行 | Cron Triggers（シラバスの取り込みなど） |
| パスキー | SimpleWebAuthn |
| Google ログイン | arctic |
| PWA | `@vite-pwa/sveltekit` |
| CSS | 素の CSS ＋ CSS 変数 |
| 授業名の改行 | BudouX |
| 画像書き出し | ブラウザ内で SVG → PNG |

## ログイン

- **登録**：Google か、メールアドレス（確認リンクを送る）
- **ログイン**：パスキーが主役。登録が終わったらパスキーを作ってもらう
- **予備**：パスキーを失くしたときのために、メールでのログインを残す
- **在籍確認**：大学のメールアドレスに確認リンクを送り、届いたらバッジを付ける。`*.ac.jp` を基本にして、`waseda.jp` のような例外は許可リストで足す。大学名の表示には [Hipo/university-domains-list](https://github.com/Hipo/university-domains-list) を参考にできるが、古いデータも混じっているので判定には使わない
- 確認メールを送るサービスは未決

## スクショ読み取り

ほかのアプリの時間割のスクショを、画像を読める AI で JSON に変換する。

### 使う AI

どちらも**無料枠でもデータを学習に使わない**サービス。

| 順番 | サービス | モデル | 無料枠 | 目安 |
|---|---|---|---|---|
| 1 | Groq | `qwen/qwen3.8-27b` | 1日1,000回、1分8,000トークン、1日200,000トークン | 1日50件くらい |
| 2 | Workers AI | `@cf/meta/llama-3.2-11b-vision-instruct` | 1日10,000 Neurons | 1日100件くらい |

- Groq の画像は1枚2,048トークン。指示文と出力を足して1回3,000〜4,000トークンくらい
- Workers AI は小さいモデルなので日本語の精度は要確認。**実際のスクショを10枚くらい集めて読み比べてから決める**
- 使わないもの：Mistral の無料枠（評価・試作用で、初期設定だと学習に使われる）、GitHub Models（試作用で本番利用は規約違反）、Gemini と OpenAI の無料枠（学習に使われる）

### 流れ

1. ユーザーが注意書きを確認して、スクショを切り抜いて送る
2. R2 に一時保存して、Queues にジョブを積む
3. Groq で読む。枠切れや、結果が JSON Schema に合わないときは Workers AI に回す
4. 両方ダメなら「明日処理します」と伝え、手入力も案内する
5. 読み終わったら画像を消して、ユーザーに知らせる
6. ユーザーが結果を確認・修正して保存する

どちらのモデルにも同じ JSON Schema で返させるので、あとでモデルを差し替えても他に影響しない。

### 限界

AI の読み取りは間違えることがある。画面と規約の両方で、保存前に見直すよう明記する。

## プライバシー

- 時間割は初期状態で非公開。承認した友だちと、見せると選んだグループだけに見える
- 時間割は「いつどこにいるか」がわかる情報なので、書き出し画像では教室名を隠せるようにする
- スクショは読み取り後に削除する
- 退会したらデータを完全に消す
